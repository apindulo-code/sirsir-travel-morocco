# عقد واجهة المرشد الذكي SirSir

## الغرض

يتصل تطبيق Flutter بخادم SirSir الخلفي، ولا يتصل مباشرةً بخدمة Gemini. يجب ألا يوضع مفتاح Gemini أو أي مفتاح خدمة سري داخل التطبيق أو مستودع Git.

## إعداد التطبيق

مرّر عنوان HTTPS الخاص بنقطة النهاية عند بناء التطبيق:

```bash
flutter build apk --release --dart-define=SIRSIR_AI_ENDPOINT=https://YOUR_API_HOST/api/chat
```

لا تستبدل العنوان بعنوان تجريبي عند إصدار نسخة عامة. إذا لم يتم ضبط المتغير، تعرض شاشة المرشد رسالة تفيد بأن الخدمة غير مهيأة ولا ترسل أي طلب.

## الطلب

`POST /api/chat`

رؤوس الطلب:

- `Accept: application/json`
- `Content-Type: application/json; charset=utf-8`

جسم JSON:

```json
{
  "message": "خطط لي رحلة لثلاثة أيام في شفشاون وطنجة",
  "language": "ar"
}
```

اللغات المدعومة في الواجهة: `ar`, `fr`, `en`, `es`.

## الاستجابة الناجحة

يجب أن يعيد الخادم حالة HTTP من فئة 2xx وجسم JSON بالشكل التالي:

```json
{
  "reply": "نص الإجابة الموجهة إلى المسافر"
}
```

أي استجابة لا تحتوي على `reply` نصية غير فارغة تُعامل كاستجابة غير صالحة.

## متطلبات أمان الخادم

- تخزين مفتاح Gemini في متغير بيئة سري على الخادم فقط.
- فرض HTTPS في الإنتاج.
- التحقق من طول الرسالة واللغة ومعدل الطلبات.
- عدم تسجيل مفاتيح API أو بيانات شخصية أو محتوى حساس في السجلات.
- إضافة مصادقة أو حدود استخدام مناسبة قبل الإطلاق العام.
- التعامل مع أخطاء Gemini والمهلة ومحدودية الحصة وإرجاع رسائل آمنة.
- عدم تقديم إجابات AI كبديل عن بيانات الناقلين أو التحذيرات الرسمية أو المشورة الطبية أو الدينية.

## الحالة الحالية

تمت إضافة عميل Flutter والشاشة والعقد أعلاه. لم تتم إضافة خادم Gemini أو نشره في هذا التغيير؛ لذلك لن تعمل الإجابات الحية حتى يُجهز الخادم ويُمرر عنوانه إلى `SIRSIR_AI_ENDPOINT`.
